# Review Keamanan, Privasi, dan Otorisasi — 28 November 2026

Review read-only terhadap kode IMM Observer. Fokus: Server Action, RLS/GRANT di `supabase/migrations/`, aliran data antarperan, sesi/kuki, dan status temuan lama (A1, A5, A7). Tidak ada kode, migrasi, policy, konfigurasi, atau data produksi yang diubah. Tidak ada berkas `.env*`, token, atau kunci API yang dibaca/dicetak.

## Ringkasan 5 temuan teratas

1. **K01 (High) — Bidang Kader bisa membaca catatan deliberasi privat lewat RLS tabel revisi.** `supabase/migrations/20261112170000_dad_scoring_collective_evaluation_v1.sql:243-245` memberi `bidang_kader` SELECT pada `collective_evaluation_revisions`, yang menyimpan `snapshot = to_jsonb(old)` berisi `strengths`, `development_areas`, `evidence_references`, `discussion_notes`, `collective_summary`, `recommendation_summary`, dan `decision_rationale`. Tabel induknya sendiri sudah menutup Kader (`:224`), tetapi jalur revisi membukanya kembali lewat PostgREST langsung.
2. **K02 (Medium) — Bidang Kader masih bisa menugaskan/mencabut Observer.** `app/dashboard/penilaian/assignment-actions.ts:15-18,64-65` memakai `staffClient(["admin_system","bidang_kader"])`, dan RLS `assignments_manage` memakai `can_manage_observer_assignments()` yang memasukkan `bidang_kader` (`20261106130000_superadmin_rubric_management.sql:29-40,64-67`). Ini bertentangan dengan `BLUEPRINT.md:145,198` dan sudah dicatat di `HANDOVER.md:723` sebagai menunggu keputusan yang sebenarnya sudah ada.
3. **K03 (Medium) — Server Action Seleksi Komisariat hanya memeriksa peran.** `app/dashboard/seleksi-komisariat/actions.ts:8-23` menerima `observer` mana pun, lalu `:25-36` dan `:110-121` meneruskan `submissionId` dari form ke RPC. Guard database saat ini masih menahan observer yang tidak ditugaskan, jadi belum ada eksploit terkonfirmasi, tetapi tidak ada pemeriksaan penugasan di lapisan aplikasi seperti pola `assertEventAssignment` di `app/dashboard/kegiatan/actions.ts:79-99`.
4. **K04 (Medium) — Pencabutan grant `anon` untuk dua tabel revisi hanya ada di server, bukan di migrasi.** `docs/STATUS-PRODUKSI-SATU-VERSI.md:17,50` menyatakan sudah dicabut dan terverifikasi, tetapi tidak ada `revoke ... from anon` untuk `assessment_moderation_revisions` dan `collective_evaluation_revisions` di seluruh `supabase/migrations/`; yang ada hanya `grant select ... to authenticated` (`20261112170000:180,245`). Instalasi ulang dari migrasi akan mengembalikan grant default Supabase.
5. **K05 (Medium) — Rotasi PAT/service-role key tidak dilakukan, dan bot debugging berjalan sebagai `ubuntu` dengan akses ke `.env.production`.** `docs/STATUS-PRODUKSI-SATU-VERSI.md:16,19,50` dan `HANDOVER.md:786`: pemilik memutuskan rotasi tidak dilakukan dan menerima risiko bot dapat membaca kunci. Kunci pernah tercatat di riwayat sesi lama. Risiko residual tetap terbuka.

## Catatan hasil pemeriksaan per topik

- **Server Action:** seluruh aksi di `app/dashboard/**/actions.ts` dan `app/dashboard/penilaian/*-actions.ts` sudah memanggil helper otorisasi (`authorizedActor`, `commissariatClient`, `reviewerClient`, `requireAdmin`, `requireModerator`, `staffClient`, `assertEventAssignment`, `assertEventActive`). Aksi yang hanya berbasis peran tanpa penugasan event ada di Seleksi Komisariat (K03) dan Laporan (K06). Aksi Impor Tes memang khusus Admin Sistem, sesuai keputusan. Aksi Peserta tidak ada karena akun belum dibagikan.
- **RLS/GRANT:** policy `INSERT/UPDATE/DELETE participants` dan bucket `participant-photos` sudah memakai `is_assigned_observer_for_event` (K10). Tabel rating/catatan/evaluasi/snapshot/publikasi sudah dibatasi ke Admin + Observer/Instruktur yang ditugaskan; satu jalur revisi masih memberi Kader akses (K01). `can_manage_events()` tidak lagi dipakai policy aktif (K11).
- **Kebocoran lintas peran:** halaman Laporan sudah mengirim DTO ringkas dan hanya memuat `private_payload` bila `canViewPrivate` (Admin/moderator); `get_event_report_rows` menyamarkan `snapshot_data` untuk Kader. Komisariat hanya melihat pengajuan miliknya (`commissariatClient` + `getDraftSubmission`). Agregat publik tidak membawa identitas. RPC `get_event_assessment_summary` membatasi Instruktur ke empat subrole koordinator yang ditugaskan dan menolak Observer/Peserta.
- **Kerahasiaan:** tidak ada kunci service-role atau API key di frontend; hanya nama variabel yang muncul dalam pesan kesalahan (`app/dashboard/pengguna/page.tsx:87`). Signed URL foto privat dibuat di Server Component dengan masa berlaku 1800–3600 detik (`lib/signed-urls.ts:23-42`). Redirect logout memakai `requestBaseUrl` agar tidak mengarah ke `localhost:3000` (K09 untuk batasannya).

## Batasan pemeriksaan

- Analisis statis saja. Tidak ada pengujian RLS live, tidak ada `SET ROLE`, tidak ada kueri yang menulis ke database, dan tidak ada akses ke server produksi.
- Status produksi (A1, A5, A7, bot Telegram, TLS) diambil dari `docs/STATUS-PRODUKSI-SATU-VERSI.md` dan `HANDOVER.md`, bukan diverifikasi langsung.
- Berkas `.env*`, token, kata sandi, dan kunci API tidak dibaca atau dicetak. Konsekuensinya, konfigurasi aktual (misalnya nilai `NEXT_PUBLIC_SITE_URL`, `DISABLE_SIGNUP`, dan daftar putih bot) tidak bisa dibandingkan dengan isi berkas.
- Tidak ada penilaian terhadap kerentanan dependency, performa, UI/UX, atau alur bisnis di luar keamanan/privasi/otorisasi. Laporan temuan arsitektur/kualitas ada di `docs/review-2026-11-28/01-arsitektur-kualitas.md`.
- Temuan bertanda "Hipotesis" (K09) belum dibuktikan dengan uji browser atau akses jaringan.
